## 第三方组件与分享限制

应用源码采用 MIT License；这不覆盖应用包中的 Qt/PySide6、FFmpeg/ffprobe 等第三方组件。

Windows 候选包随附 FFmpeg 9.0.1 Gyan “full” 静态 GPLv3-or-later 构建，包含 `libx264`。该包中的 `ffmpeg.exe`、`ffprobe.exe` SHA-256 已与 [Gyan FFmpeg 9.0.1 full 发布包](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.1)逐一比对一致；实际读取该发布包内 README 后确认，它指向 FFmpeg 源码提交 `bf1b838f2a`，并列出构建配置、启用功能、外部库及版本/修订号。该线索足以开展逐项追溯，但还没有逐个取得并校验对应源代码，也未找到与该二进制完全匹配的 Gyan 构建脚本/完整构建输入。核对摘要见 [Windows FFmpeg 依赖清单](FFmpeg-Windows-9.0.1-依赖清单.md)。

Mac 候选包实际使用 Homebrew FFmpeg 9.0.1_1 GPL-3.0-or-later，启用 `libx264`/`libx265`，并随包复制其动态库依赖；包内 `FFMPEG_BUILD_INFO.txt` 保存 Homebrew formula 元数据、依赖版本和构建选项。两平台均已确认使用 GPL 组件；[Gyan 构建说明](https://www.gyan.dev/ffmpeg/builds/)声明其 Windows 静态构建为 GPLv3；[FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)指出启用 GPL 部件会使 FFmpeg 本体适用 GPL。两平台这两个精确构建及全部外部库的对应源码、构建输入与再分发材料尚未逐项收集核验。

另对归档做了实际文件清点：Windows 包含 QtCore、QtGui、QtMultimedia、QtMultimediaWidgets、QtNetwork、QtWidgets 的 Python 扩展，以及多个 Qt 运行库/插件；Qt Multimedia 后端有 `ffmpegmediaplugin.dll` 和 `avcodec-61.dll` 等 FFmpeg DLL。最新 macOS 包还包括 QtConcurrent 及 Qt Multimedia 的多种插件；Qt Multimedia 插件目录有 `libffmpegmediaplugin.dylib`，并带有 Qt 自己的 `libavcodec.61.dylib`、`libavformat.61.dylib`、`libavutil.59.dylib`、`libswresample.5.dylib`、`libswscale.8.dylib`。Qt 6.11.2 的官方归属页将该套依赖标为 FFmpeg 7.1.3，源代码位于 Qt Multimedia 的 `src/3rdparty/ffmpeg`，并列出 LGPL-2.1-or-later、BSD、ISC、MIT、MPL-2.0 许可；但尚未把具体源文件快照、构建脚本和逐平台二进制逐项对应起来。这些库与应用额外打包的 FFmpeg/ffprobe 及其依赖是两套独立二进制，仍需分别核对版本、许可证、告知、对应源码和可替换性。Qt for Python 官方文档将 Community Edition 标为 LGPLv3/GPLv3；wheel 元数据的多重许可声明不等于发行包已满足再分发要求。参考 [Qt for Python 许可清单](https://doc.qt.io/qtforpython-6/licenses.html)、[Qt 许可说明](https://doc.qt.io/qt-6/licensing.html)、[Qt 6.11.2 FFmpeg 归属页](https://doc.qt.io/qt-6.11/qtmultimedia-attribution-ffmpeg.html)和 [Qt 6.11.2 官方源代码归档](https://download.qt.io/archive/qt/6.11/6.11.2/single/)；通用 Qt 源码归档本身不能证明覆盖了所有随包二进制及其第三方代码。

因此当前候选包只用于内部试用和反馈，核验完成前不要公开转发或上传到共享下载区。此说明不是法律意见。

## 已验证的整改方向（尚未放行）

- FFmpeg 官方许可指引要求 LGPL 路线构建时不启用 `--enable-gpl` 和 `--enable-nonfree`，并要求提供与二进制精确对应的源代码及构建说明。可避免继续依赖当前 Gyan/Homebrew GPL 包：从固定的 FFmpeg 官方源码版本分别为 Windows/macOS 构建不含 GPL/nonfree 外部库的版本；Windows 评估系统 Media Foundation H.264 编码器，macOS 评估 VideoToolbox H.264 编码器。参考 [FFmpeg 官方法律说明](https://ffmpeg.org/legal.html)。
- 可行性初测：当前 Windows 机器上的 FFmpeg 9.0.1 `h264_mf` 可成功生成 1280×720、25fps 的 H.264 MP4；3 秒合成测试输出为 Constrained Baseline profile。相同测试的 `libx264` 输出为 High profile。两者文件大小也明显不同，说明 Media Foundation 不能直接视作 `libx264` 的等质替换；还需做画质、编码参数、剪映兼容性、无硬件编码器时行为和真实成片验证。尚未更改正式导出编码器，也未验证 macOS VideoToolbox。
- 已新增 FFmpeg/x264/FreeType 双平台源码构建验证工作流和固定源码脚本，固定 FFmpeg 提交 `bf1b838f2ab88b4f8fd83443325c782ea0e0f7fa`、x264 提交 `0480cb05fa188d37ae87e8f4fd8f1aea3711f7ee` 与 FreeType 提交 `0a0221a1347e2f1e07c395263540026e9a0aa7c7`。它保留应用实际需要的 `libx264` 与 `drawtext`（字幕/字卡），在 PR 修改相关构建文件时会自动编译并运行合成视频烟测，也可以手动触发；不上传二进制工件、不打包应用。GitHub 官方说明公开仓库使用标准托管 runner 免费且不限时；本工作流未选用大型 runner 或付费服务。[GitHub Actions runner 计费说明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。当前尚未在 GitHub 运行验证。FFmpeg 官方平台页说明 Windows 可通过 MSYS2/MinGW 构建；详见 [FFmpeg Windows 平台编译说明](https://ffmpeg.org/platform.html)。新脚本的产物若通过测试，才可用于后续候选包；它不会改变既有 Gyan/Homebrew 候选包的来源或许可证状态。
- Qt/PySide 路线仍需按实际随包二进制锁定对应源代码、许可和构建配置；Qt Multimedia 内嵌 FFmpeg 与应用调用的独立 FFmpeg 必须分别列清。若采用 LGPL 动态库方式，需验证发行目录中的动态库可替换，并准备独立的对应源码/构建材料入口；安装包内保留必要的许可与来源说明，源码材料与便携应用分开提供。
- 所以“改成 LGPL FFmpeg”只是目前有官方依据、且 Windows 初测可行的整改路线，不代表许可证已合规，也不代表现有候选包可分享。只有完成两平台重建、来源闭环、动态替换/编码兼容性测试及隐私扫描后，才解除构建门槛。

## API 分析与费用估算

- DeepSeek 官方接口的模型快捷项为 `deepseek-flash` 和 `deepseek-v4-pro`；也可手动输入其他兼容服务商的 API 地址与模型 ID。其他服务商的费率及模型输出限制不同，须以其官方文档为准。
- DeepSeek 官方 API 允许的最大 `max_tokens` 为 384K，模型上下文总量为 1M。应用对官方 DeepSeek 请求设置 `max_tokens=393216` 并关闭默认思考模式，避免非思考模式默认 8K 输出限制；384K 是允许的最大值，不是固定生成量或固定费用。对其他 OpenAI Chat Completions 兼容接口，应用不发送 `max_tokens`，由服务商自己的默认策略决定；其默认值也可能导致截断。
- 发送确认框显示 DeepSeek 高峰/低谷估算，尽量使用本机同模型的历史用量；无历史时按文字量粗估输入，并以旧请求输出量作参考。输入缓存按未命中估算，输出取历史值外推，因此不是报价。还会按历史用量/视频数线性外推“10个视频+10条切片”；固定提示词开销、字幕密度及截断都会令估值偏离，输出样本若曾以 `length` 截断会提示估值可能偏低。费用最终以服务商返回 usage 与账单为准。
- 截至 2026-10-07，DeepSeek Flash 每百万 tokens：低谷输入（未命中缓存）¥1、输出 ¥4；高峰输入 ¥2、输出 ¥8。低谷含工作日高峰时段以外、周末及法定节假日；高峰为北京时间周一至周五（不含法定节假日）9:00–12:00、14:00–18:00。官方说明 `deepseek-v4-pro` 当前请求路由至 V4.1-Flash，并按 Flash 价格计费，直到 V4.1-Pro 上线。价格和路由会变化，请发送前查看 [DeepSeek 官方模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。
- 同一批素材台词会整体进入每次请求；选择少做几条主要减少模型输出，不会明显减少输入。分成多次 API 请求会重复发送上下文，并分别计费。
